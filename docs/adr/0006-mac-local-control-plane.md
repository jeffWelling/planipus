# ADR-006 — Mac local control plane: container Unix-domain socket, ratified disclosure, content-free agent surfaces

Status: accepted; implementation gated on ADR-004/005 release gates (packaging, signing, notarization) landing first

Date: 2026-07-30

Owners/reviewers: Planipus maintainers; macOS security/release review required; Server API review required for the §Server symmetry clauses

Requirements/risks: LCP-001–LCP-016, SEC-110–SEC-118, MAC-001–MAC-012, CAL-009–CAL-015

Supersedes in part: ADR-004 (§Consequences sentence "There is no incoming listener or Server communication")

## Context

`SURFACES.md` §8 records an owner decision of 2026-07-30: each edition owns a complete triad — API, CLI and MCP — with the Mac's off by default and authentication required. It defers mechanism, threat model and enablement to this record. `SURFACES.md` also already decides the *dialect*: one operation registry at `registry/v1/operations.json` (relocated from the drafted `conformance/surface/v1/` by owner decision of 2026-07-30, so that `conformance/` keeps meaning only the cross-edition behaviour corpus), one agent envelope (`schema, op, ok, outcome, data|error, warnings, next, meta`), a 41-entry safe error-code allowlist shared with the MCP adapter, fourteen frozen exit codes, and a `PARITY_DEBT` gate that must equal zero. Nothing in this decision re-opens any of that.

Four facts about the present tree bound the design.

First, the Mac edition has none of the machinery. No listener, no credential verification, no credential store for issued credentials, no audit table. The only `Bearer` strings in the Swift tree are outbound `Authorization` headers to Google. `EncryptedPlanipusRepository.currentSchemaVersion` is 5. Every element is greenfield.

Second, the Mac edition is not a signed bundle and its production Keychain path does not work. There is no `Info.plist`, no `.entitlements` and no `.app` under `macos/` outside `.build`; the only entitlement artifact is SwiftPM's debug stub carrying `com.apple.security.get-task-allow`. `KeychainSecretStore` sets `kSecUseDataProtectionKeychain: true`, which on macOS requires an `application-identifier`/`keychain-access-groups` entitlement; a probe issuing exactly the `SecItemAdd` that `save()` issues, ad-hoc-signed and unbundled, returns `-34018 errSecMissingEntitlement` on both add and delete. `SecretStoreTests` uses `InMemorySecretStore`, so the suite never observes this. `swift run PlanipusApp` cannot store the SQLCipher key or a refresh token today.

Third, the App Sandbox's treatment of local endpoints was measured rather than assumed. A sandboxed bundle signed with only `com.apple.security.app-sandbox` and `com.apple.security.network.client` binds and listens successfully on a Unix-domain socket inside its own container. The identical bundle receives `EPERM` on `bind()` and `listen()` against `127.0.0.1:0` until `com.apple.security.network.server` is added, at which point both succeed. Loopback is not exempt from the sandbox's network-inbound restriction. On a connected `AF_UNIX` socket, `getsockopt(LOCAL_PEERTOKEN)` returns a 32-byte `audit_token_t` whose trailing `pidversion` defeats PID reuse; `AF_INET` on macOS provides no peer credential at all. A sandboxed *client* cannot `connect()` into another app's container (`EPERM`); a non-sandboxed same-uid client can. A `SIGKILL`ed listener leaves the socket inode behind, and `AF_UNIX` has no `SO_REUSEADDR`.

Fourth, and most consequential, the harm this product exists to prevent is **existence and timing disclosure, not field disclosure**. `SyncPolicy` carries eleven knobs that decide *which* source events become managed copies — `timedEventsEnabled`, `allDayBehavior`, `freeEventBehavior`, `tentativeBehavior`, `needsActionBehavior`, `skipWhenDestinationInvited`, `noSyncTokenEnabled`, `sourceExclusionMarker`, `manualExcludedSourceEventIDs`, `hoursMode`/`hoursProfile`, and the horizon — none of which is a privacy field. A capability ceiling written in terms of `privacyPreset` and `privacyFields` therefore permits clearing a user's manual exclusions and blanking their `#nosync` marker while every disclosed field stays a perfectly opaque `Busy` block, which puts the job interview the user deliberately hid onto the employer's calendar. Separately, `PolicyEvaluator.swift:63` writes `policy.genericLabel` — caller-supplied free text — as the copy summary whenever `privacyPreset != .busyOnly`. And because provider writes are produced by `PlanipusSync`'s own scheduler rather than by the request that changed the configuration, a gate placed on the API call is bypassed by an attacker who mutates configuration and simply waits.

Two adversarial reviews of the candidate designs converged on those last two points and on a third: for an agent surface, the loss vector is reads, not writes. The exfiltration path is the MCP host's own shell and network tools, so restricting the Planipus adapter's egress constrains a process that was never going to be the leak. Once event content reaches a model's context it is in a provider's retained logs and no downstream control exists.

## Decision drivers

- Defeating the browser-as-local-attacker class **completely** rather than mitigating it, because a web page learning that Planipus is installed is itself the disclosure for this product's users.
- Bounding the blast radius of a stolen credential, on the assumption that it *is* stolen.
- Holding up when prompt injection reaches an agent that legitimately holds a credential.
- Keeping the Mac App Store leg viable rather than trading it away.
- Buildability by a small team without a second protocol stack.
- Real triad symmetry — one registry, one envelope, one error vocabulary — rather than two divergent transports pretending to be siblings.

## Options

**Option A — container Unix-domain socket, registry envelope over newline-delimited frames.** Zero added entitlements (measured). Structurally unreachable from any browser, any other logged-in user, any co-resident Planipus Server, and any sandboxed process. Kernel peer credentials in both directions. Requires hand-written `bind`/`listen`/`accept` on BSD sockets driven by a `DispatchSource`, since `Network.framework` exposes no `AF_UNIX` endpoint type. Breaks for sandboxed MCP hosts.

**Option B — loopback TCP on an ephemeral port under a random mount prefix, HTTP/1.1 + bearer.** Reuses the Server's dialect and the hardened `mcp/src/api-client.ts` almost verbatim. Works for sandboxed MCP hosts. Costs a permanently declared `com.apple.security.network.server`. Reachable by every browser page, so browser unreachability becomes a property of seven code paths staying correct forever; one of those seven was already wrong on analysis, because a closed port `RST`s immediately while an open one completes the handshake, so the presence oracle is a TCP-layer signal that no amount of HTTP-layer constant-latency masking can suppress. Requires a pre-authentication HTTP/1.1 parser, hand-rolled or vendored, in front of every security check with a web page holding the trigger. Provides no peer credential in either direction. Shares one port namespace across fast-user-switched accounts. Reachable by a co-resident Server, weakening the edition boundary structurally.

**Option C — XPC with a global mach service name.** Rejected without further analysis: a globally-lookupable name requires launchd registration, i.e. a LaunchAgent or `SMAppService.agent`, which this revision does not touch. An in-bundle `XPCServices` bundle is reachable only by its containing app; `NSXPCListener.anonymous()` requires the channel it is meant to create. A sandboxed client would need `temporary-exception.mach-lookup.global-name`. `xpc_listener_set_peer_code_signing_requirement` is macOS 14.4+ against a declared `.macOS(.v14)` floor.

## Decision

**Adopt Option A for transport and Option B's symmetry discipline for dialect.** The Mac gains an `AF_UNIX SOCK_STREAM` listener at `~/Library/Containers/org.planipus.macos/Data/.planipus/api.sock`, mode `0600` inside a `0700` directory, speaking newline-delimited JSON frames carrying registry operation ids and the `SURFACES.md` envelope. There is no TCP listener in any Mac build, no XPC mach service, no HTTP, and no WebSocket, SSE or long-poll on either edition. `Network.framework` cannot serve `AF_UNIX`, so the listener is BSD sockets plus a `DispatchSource`; no `swift-nio` and no HTTP parser enter the tree. The path is 73 bytes for a four-character username and 101 for a thirty-two-character one against Darwin's `sun_path[104]`, while the obvious `Data/Library/Application Support/Planipus/control.sock` measures 104 for `jeff` alone — a build-time assertion against a synthetic thirty-two-character username is mandatory.

**Net entitlement delta is zero.** The four release entitlements are `app-sandbox`, `network.client`, `keychain-access-groups`, and `files.user-selected.read-write`; the first, second and fourth were already required, and the third is a prerequisite the `-34018` result proves is missing today rather than a cost of this feature. `com.apple.security.network.server`, `application-groups`, every `temporary-exception.*` key, and `get-task-allow` in any release configuration are permanently forbidden, with CI failing the build on the last. `CFBundleURLTypes` is also forbidden: `ASWebAuthenticationSession` intercepts the reversed-client-ID scheme in-session and does not need registration, and registering one would hand any web page a LaunchServices-mediated presence oracle and an inbound channel in a design whose headline property is that neither exists.

**The API is content-free.** No operation, at any scope, in any build, returns an event title, description, location, attendee address, organiser identity or conference URL. There is no `raw_detail` flag, no `full` detail tier, and no setting that turns one on. There is no per-event enumeration: `bridge.preview` returns integer counts, an `excluded_by_reason` histogram and the disclosure manifest, with examples carrying `{observation_hash, details_redacted: true}` exactly as `policy/service.ts:242` already does. Calendar and account display names are returned as per-install HMAC pseudonyms plus stable ids unless the owner enables display names for that connection — a per-connection, default-off, presence-gated, UI-only setting — because `overview.get` returns provider-supplied `calendar.name` verbatim and a calendar named "Family Law — custody" is the disclosure without a single event being read. `bridge.preview` is bound to a ratified route id and accepts no caller-supplied horizon or selection predicate; removing the caller's window is what removes the count-differencing oracle that otherwise reconstructs a private calendar from counts alone.

**Disclosure increase is a computed property, and increasing it is UI-only at every scope.** A revision R′ over R is *disclosure-increasing* if its selection predicate can admit any source event R excluded, or it copies a field R did not, or it changes `genericLabel` while `privacyPreset != .busyOnly`, or it changes the destination account, calendar or identity. Selection containment is decided two ways, both required: structurally, by a declared per-knob monotonicity lattice over all eleven selection knobs (set containment for `manualExcludedSourceEventIDs`, interval containment for the horizon, declared orderings for the enums); and empirically, by evaluating both revisions with `PolicyEvaluator` over the observed window and detecting any excluded→included flip. Narrowing and neutral revisions are `apply` scope and self-ratify. Increasing revisions, and route creation, are refused to every credential and return `outcome:"handoff_required"` with exit 14.

**Ratification gates the effect, not the call.** A credential-authored revision is written to `lcp_pending_changes` and is not the live policy. `PlanipusSync` computes projections only from revisions whose digest appears in the ratified set held in the `control-state-v1` Keychain item; an unratified digest is a hard, audited refusal. The human drains the pending queue **on their own initiative** — no client can raise, focus or influence a window, sheet, alert or notification — under a fresh user-presence assertion, from a dialog whose assertive text the app authors from its own recomputed diff. Caller- and provider-authored strings appear only in a visually distinct untrusted style, capped at 64 grapheme clusters, stripped of newlines, control characters and bidi overrides, always beside the stable id, never as primary text; route labels shown are the last ratified label. Ratification recomputes the `SURFACES.md` §6.2 confirm digest and returns `preview_stale` on drift. Pending changes expire at 24 hours as `handoff_expired`. **There are no standing apply grants**; they are unnecessary once only widening is gated, and both adversarial reviews identified them as a documented, UI-exposed off switch for the load-bearing control.

**Credentials are never displayed, copied or written to a file.** Clients obtain `plnmac_<kid>_<43-char secret>` (256 bits from `SecRandomCopyBytes`) through an enrolment handshake: the client calls the single credential-free operation `lcp.enrol.request`; the app resolves the peer via `LOCAL_PEERCRED` (uid equality) then `LOCAL_PEERTOKEN` → `SecCodeCopyGuestWithAttributes(kSecGuestAttributeAudit)` → `SecCodeCopySigningInformation`; one pending enrolment is queued (60-second TTL, three per ten minutes, at most one outstanding) showing identifier, Team ID and path; on presence-gated human approval the credential is returned over the already-connected socket and stored by the client in its own keychain item or its own `0600` file. No pasteboard, no environment variable, no MCP configuration file, no `argv`, no file inside the app container. Digests are stored as `HMAC-SHA256(verifierKey, "planipus.mac.lcp.credential.v1|" ‖ credential)` with the verifier key in a separate Keychain item, so exfiltrating the SQLCipher file *and* its device-bound key still does not permit verification or forgery. Comparison is constant-time; a naive `==` on `Data` or `String` is a usable oracle over a socket this fast and is banned in `SECURITY.md`.

**The client authenticates the server.** Before transmitting any credential byte the client reads `LOCAL_PEERTOKEN` on its own connected fd and requires the peer to satisfy `identifier "org.planipus.macos" and anchor apple generic and certificate leaf[subject.OU] = "<TEAMID>"`. The app `stat()`s its socket path every fifteen seconds against its own bound inode and disables the plane with a must-acknowledge alert on mismatch. The `flock` on `api.lock` is authoritative for ownership: holder plus a live socket means a squatter, so unlink, rebind and alert; contended means another live instance owns the plane and this one refuses to enable and says so. Running the executable directly bypasses LaunchServices' single-instance behaviour, so that is not a safe assumption.

**Enablement is a presence-gated UI act with a bounded lifetime and unsuppressible visibility.** Disabled means no socket inode exists. Enabling requires user presence, recorded in `control-state-v1` rather than `UserDefaults` — any same-uid process can write a plist, so a boolean there was never a security property. Lifetimes are *until quit* (default), 8 hours or 24 hours; **there is no "forever"**. A `CFBundleVersion` change starts the plane disabled. While enabled: a shape-changed menu-bar glyph, an uncollapsible menu section, a must-acknowledge banner on the next foreground interaction after any enablement, and an unconditional append-only enablement history retained beyond the audit horizon — the last two exist because notifications are clearable and can be disabled in System Settings, which is exactly what the physical-access and coercive-partner scenarios do. Disabling is one unauthenticated click from the root menu, plus `Revoke everything`; quitting disables it, since there is no daemon, LaunchAgent or helper.

**Both editions become off by default and share the model.** `PLANIPUS_API_TOKENS_ENABLED`, `PLANIPUS_API_CLI_CLIENT_ENABLED` and `PLANIPUS_API_MCP_CLIENT_ENABLED` default to false; today `ApiTokenService` is constructed unconditionally at `runtime.ts:120` and passed unconditionally at `commands/api.ts:11`, so bearer authentication is on for every Planipus Server ever deployed. The Server additionally: re-applies the scope hierarchy in `storedScopes` so `apply ⇒ propose ⇒ read` is an invariant of authorisation rather than of `issue()`; emits `policy.previewed` and `conflict_response.previewed` audit facts, which both preview paths omit entirely today, letting a `propose` credential query private free/busy with no durable record; audits `POST /api/v1/sync`; threads the actor through `PlanningService`'s four hardcoded `actor_kind: "user"` sites *before* any planning route moves to bearer; moves `last_used_at` after the scope check and replaces it with an append-only use trail; adds `client_kind` provenance; rejects bearer requests carrying `Origin`, `Referer`, `Cookie` or `Sec-Fetch-Site: cross-site` and validates `Host` against an exact allowlist — a repo-wide grep finds no `Host` validation in `app.ts` today; and adopts the same ratification rule for disclosure-increasing revisions, with the browser session as the human channel. Twelve planning routes plus `sync.run` move to bearer, taking `SESSION_ONLY_WEB_OPS` from 15 to 3, with the api-token lifecycle browser-only forever citing `UX-SPEC.md:546`. Nothing in `requireSession`, `requireOrigin`, `csrfProtection` or the session cookie changes, and none of the new browser defences is applied to a cookie-authenticated route.

**MCP is gated four ways on both editions**: the surface does not exist until enabled server-side; authentication is required for every operation except `lcp.enrol.request`; `PLANIPUS_MCP_ENABLE_APPLY` keeps its exact current default-false semantics, documented precisely as removing tools from one process, never transmitted, invisible to both APIs, and therefore not a substitute for scope; and widening requires human ratification. Both adapters are stdio-only, forever — a remote transport is a new authentication and resource-server design, not a flag. The Mac adapter accepts no address input of any kind and no credential variable.

**One binary, two edition subtrees, no bridge, enforced by the type system.** `MacContext` has no URL field, so `planipus mac --url` is not an error message but a flag that does not exist; there is no `token_command`, no `--token` except to exit 2 with `token_in_argv_forbidden`, and no command that opens two contexts in one invocation. Both subtrees and both MCP tool tables are generated from the registry, which gains `editions: ["server"] | ["mac"]`, with `PARITY_DEBT` asserted per edition and required to be zero in each. The Mac client ships only inside the app bundle on both `+direct` and `+mas`; Homebrew ships the Server client only. The identity-preserving Homebrew shim proposed during design is rejected, because a user-writable shim that `execve()`s the signed helper *preserves* the peer pin while rewriting `argv` — it launders an attacker's identity into a pinned one, which is worse than no pin.

**Migration `006_local_control_plane` takes the Mac schema from 5 to 6**, adding `lcp_clients`, `lcp_pending_changes`, `lcp_ratifications`, `lcp_enablement_history` and `audit_facts`. It lands before the listener, because the Mac has no audit target at all today and an unauditable mutation surface over real calendars would be strictly worse than the Server's current posture.

### What this decision revises, and why that is now acceptable

`HANDOFF.md:31` states the Mac "must not embed the Server or a local web service", and `HANDOFF.md:319` requires entitlements to remain "outgoing-network + scoped Keychain/app-container only; no listener, daemon, LaunchAgent or privileged helper". `MACOS-AND-KUBERNETES.md:214` and `:501` and `ADR-004`'s consequences repeat the no-inbound-listener rule. Those rules are revised **narrowly and in one clause each**.

The prohibition on embedding a local web service **stands unchanged and is strengthened**. There is no web service: no HTTP, no HTML, no port, no origin, no `Host` header, no CORS, no browser client, and no browser-reachable endpoint of any kind. The rule that this ADR revises is the bare word *listener*, which is replaced by: *"an in-process, owner-enabled, container-scoped Unix-domain socket that requires user presence to enable, holds no port, is unreachable by any browser, any other logged-in user, any sandboxed process and any Planipus Server, and terminates with the app."*

This is acceptable now for reasons that did not hold when the original rule was written. The rule's purpose was to prevent an attack surface reachable from outside the app's own trust boundary and to prevent anything outliving the user's decision to quit; both purposes are served rather than weakened. The measured entitlement result means the rule's *operative* clause — the enumerated entitlement set — does not change at all, so the constraint that the rule was protecting is intact. The prohibitions on a daemon, a LaunchAgent, a privileged helper, an `SMAppService` registration and any promise of execution after termination are **not** revised and are restated here as permanent.

### What this decision does not decide

The `+mas` release itself remains optional and separately gated. Key rotation, recovery and export remain open ADR-005 gates and are untouched. The Mac gains no conflict-response engine, no protected-hours fences and no Smart Meetings; symmetry is of *shape*, not capability, and absent capabilities produce absent commands rather than `not_implemented` stubs. Whether the Server's bare SHA-256 credential digest should be upgraded to the Mac's keyed construction is deferred. Whether a narrower `conflict-preview` scope should exist is deferred. `SURFACES.md` §9's six open owner decisions are unaffected except where explicitly resolved above (the Phase 3 posture is resolved as the twelve-route promotion with ratification; the operator socket ships with exactly one route; the documented default agent credential scope is read+propose).

### Edition autonomy is reaffirmed

The Mac triad calls only the Mac; the Server triad calls only the Server. There is no pairing, no discovery, no fallback, no shared credential, no shared audit store, no shared session, and no configuration in which either client or either adapter can address the other edition — because neither has a field capable of expressing an address. Distinct credential prefixes reject each other with an indistinguishable response body and an audited `foreign_edition_credential` reason code. The existing network conformance test, which already proves the Mac app never contacts a Planipus Server, is extended to both client subtrees and both adapters. Migration between editions, if ever built, is a human exporting a file and a human importing it.

## Consequences

Positive. The browser-as-local-attacker class is deleted rather than mitigated: no CORS reasoning, no DNS rebinding, no Private Network Access dependency, no `Host` allowlist, no `Sec-Fetch` filtering, no loopback-alias class, and no presence oracle. The declared entitlement set is unchanged, so Mac App Store distribution remains viable and no reviewer-visible inbound-network entitlement appears on a privacy-marketed app. A stolen credential can pause, resume, sync, reconcile, narrow, and read counts and health — it cannot read event content, widen any disclosure, create a route, touch OAuth, mint or widen a credential, enable itself, or act on an account added after it was enrolled. An agent whose context is poisoned inherits exactly that envelope, cannot provoke a dialog to time against a user it has primed, and cannot exfiltrate event content because none is returned. The audit paradox dissolves: a content-free log can honestly answer "did anything read my calendar?" because there was nothing to read.

Negative. Some genuinely useful agent tasks become impossible, and sustained pressure to add a detail flag should be expected and refused. Route creation and any widening require a human at the Mac, which users who want an agent to configure their routing will experience as refusal. Browser clients, a local dashboard and browser-extension integration are permanently foreclosed. Sandboxed MCP hosts cannot reach the socket, which is a host-dependent failure Planipus can only name, not fix. The Mac client is not on `PATH` out of the box. Turning the Server's bearer surface off by default breaks every deployed automation on upgrade. Enrolment is more machinery than a Copy button. Two disjoint audit stores mean no unified cross-edition view, ever.

Follow-up work, tests and gates. Packaging is Phase 0 and blocks everything: bundle, `Info.plist`, entitlements, Hardened Runtime with Library Validation, Developer-ID, notarization, stapling, and the Application-Support→container database migration performed copy → verify → remove with the original intact on any error, given `ProductionStoreGate`'s fail-closed semantics and the absence of any rekey path. A bundled-app test must exercise the real `KeychainSecretStore` rather than the in-memory double. New conformance families: monotonicity-lattice property tests over all eleven selection knobs; a ratification family asserting the coordinator refuses unratified digests; a red-team regression family in which each of an events-list endpoint, a detail flag, a caller-supplied horizon, a standing grant, a client-triggered modal, an on-disk credential, a `--url` on the Mac subtree, a bare-PID peer check, a CORS header, a cross-edition credential, and an apply attempted without ratification must fail closed and produce exactly one audit row containing no sensitive content. The existing 91-case closed-corpus gate must pass unchanged; any reconciliation requiring a case edit is a behaviour change needing its own record. `REQUIREMENTS.md` and `TRACEABILITY.md` rows land in the same commit, per `scripts/docs-gate.mjs`.

Deprecation and rollback boundary. The listener is a separable module behind a `LocalControlPlane` protocol; disabling it removes the socket and leaves the app exactly as it is today, so rollback is a feature flag and a menu item, not a migration. Schema 6 is forward-only; the tables are additive and inert when the plane is disabled. The Server changes are individually revertible except the `PlanningService` actor threading, which is a strict correctness improvement that should not be reverted.

## Validation / revisit trigger

Before shipping, verify on a clean machine with a signed, notarized bundle: that a terminal holding no TCC grant is prompted rather than silently denied when connecting to the container socket; that a differently-signed application querying the `org.planipus.macos` keychain access group receives `errSecMissingEntitlement` rather than a user-facing prompt; that `LOCAL_PEERTOKEN` is readable by the *client* on its connected fd, since the mutual-verification control depends on it; that a sandboxed adapter's `EPERM` is distinguishable from a TCC denial at the errno level well enough for `doctor` to be honest; and that `unlink`-then-`bind` of a live listening path behaves as described on current Darwin. Revisit this decision if Apple changes container reachability or `sun_path` semantics, if a first-party `AF_UNIX` server abstraction lands in `Network.framework`, or if a measured user-research result shows the content-free read surface makes the agent integration unusable rather than merely narrower — in which case the correct response is a new record arguing for a specific, minimal, presence-gated, time-boxed disclosure, not the reinstatement of a detail flag.

## Supersedes / superseded by

Revises ADR-004 §Consequences ("There is no incoming listener or Server communication") in its first clause only; the second clause stands. Does not supersede ADR-005. Fulfils the deferral recorded at `SURFACES.md` §8.
